# Product3DViewer for Framer

A fully featured, Framer-ready 3D product viewer built to showcase photorealistic models with intuitive camera controls, configurable lighting, and fast loading defaults. This guide explains how to install the project, import the component into Framer, and tailor every property control for your experience.

The Framer component lives alongside the Insight Trends Dashboard Jekyll site in this repository. You can iterate on the dashboard and the 3D viewer independently while sharing the same toolchain and Git history.

## Prerequisites

- **Node.js 18+ / npm 9+** – Matches the dashboard tooling and is required if you need to rebuild or lint shared scripts.
- **Ruby 3.1+ with Bundler** – Only necessary if you intend to run the Jekyll dashboard locally. The Framer component itself does not require Ruby.
- **Framer account** – A Starter plan or higher is recommended so you can import code components via GitHub.
- **WebGL 2–capable browser** – Ensure you preview the component in browsers that support hardware-accelerated 3D rendering (Chrome, Edge, Safari 17+).

## Project setup

All commands reuse the existing tooling defined at the repository root.

```bash
# Install JavaScript tooling
npm install

# Optional: install Jekyll dependencies if you also work on the dashboard
bundle install

# Run lint/tests shared by dashboard and component scripts
npm run lint
npm test
```

> The Product3DViewer component is implemented as a Framer code component and does not require a separate build step inside this repository. The `framer/` directory contains documentation, configuration presets, and any supporting assets you add.

## Importing into Framer

1. **Fork or clone** this repository so you can reference it from Framer.
2. In Framer, open your project and go to **Code → Connect GitHub Repository**.
3. Authenticate with GitHub and select your fork that contains the `framer` directory.
4. Choose the branch `docs/framer-product3dviewer-readme-e01` (or your main integration branch) and import the `Product3DViewer` code component.
5. Framer will detect the component and surface all property controls defined in `Product3DViewer.tsx` (or the equivalent source file in your branch). Drop the component onto the canvas and start customizing.

If you prefer manual imports, you can copy the component files from your fork into a Framer project via **Code → New Component** and paste the source directly.

## End-to-end usage workflow

1. **Prepare your assets**:
   - Convert your 3D model to GLB/GLTF with embedded materials.
   - Optimize texture resolution (2K or lower is usually sufficient) and compress the mesh (Draco if supported).
   - Place the GLB file in Framer’s asset panel or host it on a CDN with CORS enabled.
2. **Place the component** on the canvas. Resize the frame to match your product tile, hero section, or interactive module.
3. **Bind the `modelUrl` property** to your GLB asset. The component supports remote URLs and Framer-hosted files.
4. **Adjust camera presets** to frame your product. Configure azimuth, elevation, and distance to highlight key angles.
5. **Tune interaction controls** depending on the target device. For marketing sites you might limit rotation to a hero angle; for configurators you can enable full orbit, zoom, and pan.
6. **Style the materials and lighting** to match brand direction. Use HDR environment maps for realistic reflections or fallback to the solid background for performance-heavy pages.
7. **Publish and test** on the staging link generated by Framer. Verify loading behavior on both desktop and mobile. Adjust performance settings if the model is too heavy.

## Property controls

Each property control below is available in Framer’s right-hand property panel once the component is placed on the canvas. Defaults are chosen to balance high quality visuals with fast initial load times.

### Camera

| Property | Type | Default | Range / Options | Notes |
| --- | --- | --- | --- | --- |
| `initialAzimuth` | Number (°) | `135` | `0 – 360` | Horizontal orbit angle when the viewer loads. Combine with `autoRotate` for dynamic heroes. |
| `initialElevation` | Number (°) | `25` | `-30 – 75` | Vertical tilt. Negative values look up from below; positive values look down from above. |
| `initialDistance` | Number | `4.5` | `1 – 12` | Distance between camera and model origin (in scene units). Smaller values zoom in. |
| `minDistance` | Number | `2` | `0.5 – initialDistance` | Clamp zoom-in to protect against clipping through the mesh. |
| `maxDistance` | Number | `6` | `initialDistance – 20` | Clamp zoom-out to keep the product readable. |
| `autoRotate` | Boolean | `true` | `true` / `false` | Enables slow continuous orbit around the model. Use for hands-off product spins. |
| `autoRotateSpeed` | Number | `0.6` | `0.1 – 2` | Revolutions per second when `autoRotate` is on. Lower values feel smoother for hero sections. |
| `resetTarget` | Boolean | `true` | `true` / `false` | When enabled, double tapping or pressing the reset button snaps back to the initial camera pose. |

### Interaction

| Property | Type | Default | Range / Options | Notes |
| --- | --- | --- | --- | --- |
| `enableRotate` | Boolean | `true` | `true` / `false` | Allows drag/touch orbiting. Disable for static hero renders. |
| `enableZoom` | Boolean | `true` | `true` / `false` | Enables scroll/pinch zoom. Combine with `minDistance`/`maxDistance` to constrain range. |
| `enablePan` | Boolean | `false` | `true` / `false` | Allows two-finger drag to shift the model within the frame. Recommended for configurators. |
| `rotateSensitivity` | Number | `1` | `0.4 – 2` | Multiplier for pointer/touch rotation speed. Higher values feel snappier on large screens. |
| `zoomSensitivity` | Number | `0.8` | `0.2 – 1.5` | Controls scroll wheel and pinch responsiveness. Lower values prevent motion sickness. |
| `doubleTapToReset` | Boolean | `true` | `true` / `false` | Double-tap/two-finger tap resets the camera when enabled. Useful on mobile. |
| `showControlsOverlay` | Boolean | `true` | `true` / `false` | Toggles the on-canvas overlay with reset, zoom, and fullscreen buttons. |

### Materials

| Property | Type | Default | Range / Options | Notes |
| --- | --- | --- | --- | --- |
| `exposure` | Number | `1` | `0.5 – 1.8` | Global scene exposure multiplier. Increase for darker models. |
| `baseColor` | Color | `#ffffff` | Any HEX/RGBA | Applies a tint multiplier to the model’s base color. Set to neutral for PBR-accurate renders. |
| `metallic` | Number | `0.2` | `0 – 1` | Overrides metallic factor if the GLB lacks PBR data. Higher values add reflective sheen. |
| `roughness` | Number | `0.5` | `0 – 1` | Lower values produce shinier surfaces; higher values diffuse reflections. |
| `normalScale` | Number | `1` | `0 – 2` | Scales the strength of normal maps embedded in the model. Use `0` to disable. |
| `clearcoatStrength` | Number | `0.1` | `0 – 1` | Adds clearcoat highlight for glossy plastics. |

### Lighting

| Property | Type | Default | Range / Options | Notes |
| --- | --- | --- | --- | --- |
| `keyLightIntensity` | Number | `1` | `0 – 3` | Primary directional light brightness. Works alongside environment lighting. |
| `keyLightColor` | Color | `#ffffff` | Any HEX/RGBA | Tint for the key light. Warm tones pair well with lifestyle scenes. |
| `fillLightIntensity` | Number | `0.5` | `0 – 2` | Softens contrast from the opposite side of the key light. |
| `rimLightIntensity` | Number | `0.25` | `0 – 1` | Adds a faint back light to outline silhouettes. |
| `shadowSoftness` | Number | `0.6` | `0 – 1` | Adjusts PCF softness for shadows. Higher values reduce banding but cost GPU time. |
| `castShadows` | Boolean | `true` | `true` / `false` | Toggles dynamic shadows from directional lights. Disable for lightweight cards. |

### Environment

| Property | Type | Default | Range / Options | Notes |
| --- | --- | --- | --- | --- |
| `environmentMap` | File / URL | `"studio-soft.hdr"` | Any HDR file | HDR image used for reflections and global illumination. Provide an HDR asset via Framer or external URL. |
| `environmentIntensity` | Number | `1` | `0 – 2` | Multiplier for environment lighting brightness. |
| `environmentRotation` | Number (°) | `0` | `0 – 360` | Rotates the HDRI around the model for precise highlight control. |
| `backgroundMode` | Enum | `"environment"` | `"environment"`, `"color"`, `"transparent"` | Chooses whether to display the HDR backdrop, a solid color, or transparency. |
| `backgroundColor` | Color | `#0f1115` | Any HEX/RGBA | Only applied when `backgroundMode` is `"color"`. |
| `fallbackColor` | Color | `#151821` | Any HEX/RGBA | Solid color shown while the HDRI loads or if the URL fails. |

## Example configurations

### Variant 1 – E-commerce product card

- Purpose: Quick spin interaction on PDP tiles.
- Key settings:
  - `autoRotate: true`, `autoRotateSpeed: 0.45`
  - `enablePan: false`, `enableZoom: false`
  - `environmentMap: "studio-soft.hdr"`, `environmentIntensity: 0.8`
  - `backgroundMode: "color"`, `backgroundColor: "#f3f5f8"`
- Notes: Keeps interactions simple and highlights product finish with soft lighting.

### Variant 2 – Hero reveal with HDR reflections

- Purpose: Standalone landing hero block.
- Key settings:
  - `initialAzimuth: 210`, `initialElevation: 22`
  - `autoRotate: true`, `autoRotateSpeed: 0.75`
  - `enableZoom: true`, `enablePan: true`
  - `environmentMap: "hdr/atrium-loft.hdr"`, `environmentIntensity: 1.3`, `exposure: 1.1`
  - `keyLightIntensity: 0.6`, `rimLightIntensity: 0.4`
- Notes: Combines HDR reflections with rim lighting for a premium look. Consider 4K HDR only for hero sections.

### Variant 3 – Performance-first mobile embed

- Purpose: Embed in feature-rich pages while keeping FPS high on mobile.
- Key settings:
  - `autoRotate: false`
  - `enableRotate: true`, `rotateSensitivity: 0.85`
  - `environmentMap: null`, `backgroundMode: "color"`
  - `castShadows: false`, `shadowSoftness: 0.3`
  - Simplified GLB under 3 MB, Draco compressed
- Notes: Sacrifices advanced lighting for consistent frame pacing on low-end devices.

## Performance recommendations

- **Keep GLB assets under 5 MB** for general marketing use. For configurators, lazy-load heavier variants only when needed.
- **Prefer mesh simplification and texture atlasing** to minimize draw calls.
- **Disable shadows and lower environment intensity** on mobile breakpoints if you notice stutter.
- **Use `fallbackColor`** to ensure the viewer never flashes white while HDRIs stream.
- **Test with Framer’s device previews** (especially iPhone 12 and Pixel 5) to validate touch interactions.

## Assets and licensing

No HDR or GLB assets are bundled in this repository. When adding your own:

- Source HDR environments from libraries such as [Poly Haven](https://polyhaven.com/hdris) (CC0) or [HDRI Haven](https://hdrihaven.com/).
- Ensure third-party models comply with your product licensing. Prefer CC0 / Royalty-Free assets for demos.
- Document any added files in this section with the asset name, author, URL, and license.

## Troubleshooting

| Issue | Resolution |
| --- | --- |
| Model loads black or overly dark | Increase `exposure`, switch to a brighter HDRI, or confirm that the GLB includes baked textures. |
| Viewer appears blurry | Verify your Framer canvas scale is 1× and that `pixelRatio` isn’t capped in the component. High DPI screens may need adaptive resolution settings. |
| Gestures feel sluggish on mobile | Lower `rotateSensitivity`, disable `castShadows`, and reduce texture resolution. Consider shipping a lower poly LOD. |
| HDR environment fails to load | Check CORS headers on the hosting server. Use HTTPS URLs and provide a `fallbackColor`. |

For deeper debugging, open the browser dev tools, inspect the `Product3DViewer` component logs, and verify network responses for asset downloads.
